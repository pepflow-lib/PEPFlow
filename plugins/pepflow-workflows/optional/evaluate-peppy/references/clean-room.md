# Clean-room non-leakage rules

This reference is safe to supply to every generation worker. Apply it to every attempt, including both PGM conditions and later repetitions of the same condition. The worker protocol and this reference override broad permissions in generic skills to consult examples. Use only the controller-frozen selected condition and repetition; unselected cases are not additional work.

## Allowed inputs and scoped assistance

Derive the result de novo using only the supplied common assumptions and own case packet, the frozen approved generic framework code, skills, dependencies and documentation required for the workflow, and artifacts created within this attempt. Search only paths on the supplied allowlist. Generic API lookups are allowed within approved documentation; do not follow links to excluded examples or target solutions. The allowlist must cover reviewed transitive imports/resources, not a wildcard copy of a plugin or repository. Generic smoke inputs and empty notebook skeletons contain no target answers and must not be derived by reading a solved example.

Two frozen input allowances preserve the condition distinctions:

- Only a `pgm_with_sos` worker may use the fixed SOS aid supplied in its own packet, including its implementation notes. It is declared assistance, not independently discovered mathematics, and remains a candidate requiring verification against the worker's own certificate. The allowance does not extend to the aid's source notebook, surrounding cells, outputs, multipliers, remainder matrices, proof, or provenance material. A `pgm_without_sos` worker must not access the fixed aid or its source. It may discover and use its own SOS decomposition within the attempt.
- The BPPM worker may use the conjectured rate supplied in its own input. This does not authorize retrieving a BPPM proof, certificate, solution, or any additional hint.

All other rates marked unknown remain unknown at dispatch. A metric marked unknown remains unknown at dispatch. These exceptions authorize only the supplied text, not new retrieval or expansion of target-specific material.

## Prohibited sources and actions

Do not inspect, search for, open, quote, copy, or derive hints from any target-specific pre-existing result in this repository, another checkout, external sources, or any form of history. Prohibited sources include:

- Existing example directories, target setup implementations, reference notebooks, paper proof sections, PDFs, TeX proofs, theorem files, certificates, saved duals, JSON artifacts, test answers, tests encoding expected results, logs, generated outputs, and run folders.
- Git commits, diffs, branches, tags, stashes, reflogs, deleted or renamed files or results, other worktrees or checkouts, backups, and cached rollouts.
- Prior chats, agent transcripts, inherited solution summaries, shell or editor history, open proof tabs, earlier repetitions, sibling condition directories, and other workers' inputs, outputs, logs, messages, or process command lines. This includes the other PGM condition and the paired repetition's artifacts or answers.
- Controller/evaluator documents, evaluator target tables, `evaluation-operations.md`, controller measurement/continuation scripts, aggregate reports, online solutions, and target-specific literature searches.

Do not run repository-wide searches for the target algorithm, conjecture number, metric, rate, or proof. Do not infer the solution from prohibited tests, filenames, diffs, traces, or summaries. Active skills' general reference permissions do not override these restrictions.

Only write this attempt's generated outputs. Do not edit frozen framework source, installed skills, shared dependencies, supplied inputs, or evaluation rules. If a generic instruction points to an excluded example, use the approved generic prose or supplied empty presentation skeleton; preserve the mathematical workflow's completion gates. Apply only the evaluation presentation override supplied in the worker protocol; it does not waive mathematical requirements or authorize new source/API implementations.

## Independent context and runtime

The controller supplies a fresh context for every condition and repetition without its conversation, prior solution summaries, other attempts' material, or evaluator material. A shared PGM `pair_id` links the same repetition number for later analysis only; it permits no shared context, artifacts, hints, or runtime state. A worker must not seek access to other sessions, shared reports, or other attempts. Generic preflight uses the same actual worker tool route and approved interpreter as the attempt; it supplies no target inputs and does not launch a browser or test image-display capability. Use the attempt's own Python/Jupyter kernel, mutable solver state, temporary directories, logs, and writable caches, together with the campaign's frozen approved source and skills. Do not communicate mathematical hints between workers. Manage only this attempt's owned execution handles and jobs.

The controller supplies frozen operational settings at initial dispatch; subsequent continuation messages contain only `Proceed with the next step under the existing case instructions.` It must not provide coefficients, bases, rates, hints, proof repairs, evaluator feedback, or another attempt's result. A worker must derive its own mathematical content within its frozen budget.

## Exposure handling and honest audit

Apply the supplied worker-safe [tool recovery policy](tool-recovery.md). An unresolved local import, generic search-path diagnostic, failed static check, or the declared limitations of instruction-only isolation do not by themselves establish prohibited exposure. Record and repair ordinary tool/configuration errors using the reviewed adapter and attempt-owned files, then rerun the required checks in this same session and original budget. Do not request new permission for already authorized mechanical repairs or discard the attempt simply because a check initially failed.

If prohibited material is actually exposed or consumed by a tool influencing this attempt, stop reading immediately. Record the source, what was exposed, and when it occurred; report the exposure and stop the attempt as `contaminated`. Preserve actual outputs and the preregistered slot. Do not silently restart, replace it, or present its proof as an independent reproduction. A denied read can be recoverable, provided the diagnostic/filename itself exposed no prohibited information.

A confirmed unapproved generic read remains a recorded boundary deviation: continue only under a narrowly defined equivalence/permission rule frozen before dispatch, never by silently expanding the allowlist. Concrete evidence of a potentially prohibited read/output requires bounded operational triage with mathematical work suspended and the original clock running. Resume only if that concern is resolved; otherwise stop as `error` (or `timeout` at the original deadline), with `access_status=unresolved` and a concrete reason, rather than claiming confirmed contamination. Routine incomplete access visibility alone is not such an incident. Do not bypass required checks, edit frozen source, weaken mathematical criteria, or obtain new mathematical assistance during recovery.

Maintain a consulted-source record listing every file, command, and external resource actually consulted. Preserve available source-access and tool logs under the attempt's `supplementary/`, with a compact list and integrity exceptions at closure. Declare whether prohibited sources were used or encountered, and state any limits in observability. A worker declaration does not establish a complete audit by itself; the controller separately reports what available logs support.

Keep incident evidence and repair outcomes in existing events/access records. Distinguish configured search roots, blocked attempts, actual reads, and content exposure. An operational success does not certify all access history, and a worker's provisional `contaminated` label is not itself evidence of prohibited content.

Record `access_control=enforced` or `access_control=instruction_only` with the actual mechanism and limitations. Folder separation, a worktree, and a written policy do not alone enforce read isolation. Do not certify absence of exposure beyond available controls and logs. These rules govern information supplied or retrieved during the attempt; neither access setting proves absence of relevant knowledge in model training.
