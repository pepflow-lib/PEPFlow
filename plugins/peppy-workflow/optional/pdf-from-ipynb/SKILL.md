# PDF from IPYNB

Turn the result established in an output `.ipynb` into a readable mathematical note with explicit assumptions, theorem statements, and complete proofs. Deliver both the PDF and the exact `.tex` source used to compile it by default. This is an optional publishing step after analysis, not a sixth required analysis block.

## Invocation

Accept a notebook path and optional output path, title, and language. For example:

```text
$pdf-from-ipynb examples_peppy/my_algorithm/my_algorithm_example_lyap.ipynb
```

If no path is given, use the final output notebook identified in the current conversation. Ask for a path only if several candidates remain plausible; do not choose a different experiment merely because its notebook was modified most recently. Match the notebook's prose language unless the user specifies another language.

Resolve relative notebook paths and explicitly supplied output paths from the invocation directory before changing working directories. The notebook's resolved parent determines the default destinations and supplementary paths.

Read the shared [output layout policy](../../references/output-layout.md) and [references/workflow.md](references/workflow.md) before producing the document.

## Essential boundaries

- Preserve the algorithm, assumptions, parameter ranges, and strength of the notebook's result. Numerical agreement, a solver status, or a stored `proof_valid` flag alone cannot establish a theorem.
- Read both the proof exposition and its supporting calculations. Produce a complete mathematical argument, rather than printing the notebook or renaming a proof outline as a proof.
- Keep unproved claims visibly separate from established results. If a central proof is missing, produce a clearly marked draft with the exact gap; do not invent a certificate or silently add assumptions.
- Keep this step focused on exposition and verification of the existing result. Do not restart coefficient searches, run Blocks 1-5, or modify the source notebook merely to export it.
- The PDF must compile and be visually checked before it is reported as ready. If a required tool is unavailable, finish the editable source and state the remaining build or review limitation accurately.

## Deliverables

Resolve the input notebook's actual parent directory before creating files. Produce the following matching pair beside the notebook by default:

- Final PDF: `<notebook-parent>/<notebook-stem>_theorem_proof.pdf`.
- Exact, editable LaTeX source used to build that PDF: `<notebook-parent>/<notebook-stem>_theorem_proof.tex`.
- Compilation logs, intermediate files, rendered previews, export scripts, verification copies, and other auxiliary files: `<notebook-parent>/supplementary/pdf-from-ipynb/<notebook-stem>/`.

A request to make a PDF includes the matching `.tex` deliverable unless the user explicitly asks for PDF only. When the user specifies a PDF output path, default the source to the same directory and filename stem with a `.tex` extension; honor a separately specified source path.

The working directory is relative to the source notebook, regardless of the current shell directory or repository root. Do not place files generated by this optional task in repository-level `build/` or `state/`. Keep the main notebook and setup file in their existing locations; `state/` remains reserved for the main analysis steps and their required data. Create directories and auxiliary files only when needed; avoid duplicate reports, backup variants, and unnecessary intermediate artifacts. Preserve existing user files without blanket relocation or deletion.

Use the delivered `.tex` file as the canonical compilation input, with a complete preamble, package and macro definitions, and document body. Direct build outputs to the supplementary working directory, inspect the resulting PDF, then copy that checked PDF to its final destination. Do not reconstruct a different TeX file afterward or modify the delivered source without rebuilding and reviewing the PDF. Keep any required local assets under `supplementary/` with paths that resolve from the delivered source; the source must not depend on disposable build files. For an explicit PDF-only request, keep working TeX in the supplementary directory without presenting it as a requested deliverable.

Report both delivered file paths and confirm that the PDF was compiled from the delivered `.tex`, unless the user explicitly requested PDF only. State whether the principal result is proved, conditional, or still a draft, and whether compilation and visual review passed. If no PDF was produced, report that fact and the available source path instead of claiming a completed pair. Mention any proof gap or unperformed execution check that affects confidence.
