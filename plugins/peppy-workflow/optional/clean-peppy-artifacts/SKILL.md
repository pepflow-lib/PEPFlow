# Clean Peppy Artifacts

Preserve the selected examples' existing workflow and publication deliverables, their transitive dependencies, and explicitly requested additional deliverables. The delivery contract includes more than the main notebook's Run All inputs. Remove historical source authentication with minimal edits to existing files and remove only demonstrably disposable debris. Broader notebook rewriting, dependency refactoring, and workflow redesign belong to separate tasks.

## Invocation and scope

Accept a notebook, completed example directory, or explicitly selected delivery directory. Use the current target when unambiguous; ask only when the target, notebook selection, or source/destination boundary cannot be determined. Honor review-only requests without changing files.

Selecting cleanup authorizes the narrowly scoped source-authentication and delivery-reference edits below and verified removal of disposable debris; do not request another general inventory approval. It does not authorize dropping protected workflow or publication deliverables. Creating, updating, or reviewing this skill does not invoke cleanup. If attached to generation, wait until the requested notebook, review, and any requested exports are complete.

For an original evaluation campaign or frozen source archive, use the selected examples to prepare a distinct delivery destination and leave the source records untouched. Resolve a missing destination before writing. A directory already identified as a distribution can be cleaned in place. Do not create a second archive or backup tree by default.

Read the [distribution workflow](references/workflow.md) before acting. Consult the existing [output layout](../../references/output-layout.md), active core workflows, and publication/run instructions to identify required deliverables and handoffs. Read the manuscript when available; report its absence and do not claim a paper-reference audit without it. This skill's limited source-authentication and delivery-reference exceptions govern distribution cleanup even where shared guidance says to preserve notebook bytes. Leave shared instructions, core workflows, and unselected source archives unchanged.

## Retention contract

- Preserve the notebook's mathematical statements, assumptions, computations, proof checks, cell structure, saved outputs, and metadata. Keep notebook and retained-file bytes unchanged except for minimal source-authentication edits and the verified delivery-reference migration below. Preserve mathematical outputs; a migration may update only its corresponding saved path/ID strings. Keep cell count, order, IDs, types, execution counts, and paper references; do not add, delete, merge, or reorder cells. Preserve the existing five core skills, detailed workflows, Claude commands, and shared instructions; do not switch workflow versions, regenerate Blocks 1-5, or revise the proof.
- Protect each main setup module, all completed B1-B5 workflow states, and the required dense/relaxed results, certificates, basis/rank/dual evidence, closed-form handoffs, and their transitive dependencies. Preserve existing `state/` and `supplementary/` roots with their meaningful workflow/publication content. These are delivery artifacts independently of whether the main notebook reads, inlines, or regenerates them; neither regeneration nor absence from a default Run All is a deletion rationale.
- Preserve existing deliverables and evidence required by the workflow, manuscript, or publication/run instructions, including their assets and dependencies. Treat uncertain publication roles as retained exceptions. A notebook containing an argument does not by itself make its existing paper evidence or handoff files disposable. If an essential argument exists only externally, retain it and report the notebook's coverage gap without rewriting the proof.
- Remove replay requirements that framework, example, or proof source match historical file bytes, archived source strings, or recorded source hashes. Apply the [scoped transformation](references/workflow.md#2-remove-historical-source-authentication). Preserve numerical/proof certificate data and actual verification. Preserve payloads and IDs except for the narrowly verified path-metadata migration below. Historical source metadata inside a certificate may remain inert to preserve its ID; it does not require authentication-only helpers or source archives to ship. Numerical certificate/data archives remain protected artifacts when they serve the delivery contract.
- Retain code, data, configuration, environment specifications, and assets required by any protected artifact, workflow consumer, publication deliverable, or supported execution path after that transformation, including indirect reads and remaining integrity checks. Preserve working relative paths and the intended environment; retained artifacts must work directly, without a restoration step.
- Resolve required evidence, basis-search, rank, and certificate references from retained states and supported helpers to coherent shipped artifacts, following the [delivery-reference rules](references/workflow.md#required-artifact-references). Historical rejected-trial logs are not required solely because a saved record mentions them. Missing required evidence prevents a completion claim: recover it or validate it from sufficient saved data, without deleting the reference or inserting a placeholder. Necessary path/ID metadata migrations may update an affected certificate ID and its references only after proving that numerical/proof data and mathematical outputs are unchanged.
- Remove only files demonstrated to be disposable outside those protected roles, such as expired task-owned caches, debug dumps, render previews, temporary build products, or abandoned authoring scratch files. A filename, apparent duplication, successful notebook replay, or lack of a notebook import alone does not establish disposability.
- Keep unresolved dependencies and unrelated or concurrently edited files. Continue with independently justified removals and report remaining exceptions. Use literal resolved paths inside the selected target; do not traverse symlinks/junctions or apply repository-wide Git cleanup.

## Verification and completion

Verify the protected artifact inventory and its workflow/publication consumers before testing execution. Use a disposable copy of the proposed retained delivery, including scoped source-authentication and delivery-reference edits, to verify imports and execute the candidate notebook in a fresh kernel. Inspect writes and path resolution first so the run cannot fall back to removed source files or modify originals. Preserve the intended package versions and interpreter.

Existing notebook computations and state writes are allowed only in the disposable validation tree. Preserve and package the retained artifacts' pre-replay bytes; never replace delivered states with regenerated validation outputs. Do not launch additional discovery, regenerate existing workflow states to fill an evidence gap, repair mathematical cells, skip failures, or change the mathematics. Recovery of missing required evidence follows the detailed workflow. If execution is unavailable or exceeds the task's resources, report exactly what was checked and leave full replay unverified. Static inspection alone does not establish successful execution, and successful execution alone does not establish a complete workflow or publication delivery.

Compare fresh-kernel execution counts with the baseline and preserve numbering used by the paper. Run validation setup without consuming notebook execution numbers. Check that differences contain only authorized source-authentication/reference edits or validated recovery of missing evidence, protected mathematical content and artifact data are preserved, required references resolve coherently, required setup/state/supplementary files remain, and core workflow files are unchanged. Report source edits, preserved workflow/publication artifacts, removals, exceptions, manuscript availability, and actual verification in the response or an already requested PR description. Do not generate cleanup reports, manifests, backup copies, per-file pointers, or restoration tools by default. Follow the detailed workflow for safe validation and removal.
